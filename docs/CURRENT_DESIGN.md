# PVTKRRX Current Design

Updated: 2026-03-24

## Purpose

This is the canonical description of how PVTKRRX is intended to work today.
If another document disagrees with this file, this file wins unless that document is explicitly marked as a historical planning record.

## Runtime Model

PVTKRRX is one codebase with three active pieces:

1. Hosted relay on the public site:
   - serves hosted manifests and configure UI
   - encrypts hosted config tokens
   - stores LAN pair state and account data when KV-backed storage is configured
   - handles Stremio AuthKey linking and account-scoped access checks
   - can run hosted connection checks for public endpoints from the configure UI, but must not probe loopback/LAN/private targets
2. Local runtime on the Windows host:
   - serves `PC Local` manifests and config-backed addon routes
   - exposes built-in `/file` and `/playback` endpoints
   - provides local admin routes such as `/local-config`, `/auto-provision`, `/network-info`, and local qBit control
3. Electron desktop wrapper:
   - packages and launches the local runtime on Windows
   - performs startup checks and local auto-provision helpers
   - sends LAN pair heartbeat updates and Stremio launch pulses

## Route Model

| Route | User | Install path | Playback path | Main rule |
|---|---|---|---|---|
| `PC Local` | Same Windows machine running PVTKRRX | `http://127.0.0.1:7000/local/manifest.json?mode=local` | Local `/file` and `/playback` routes | Same-PC only |
| `LAN Bridge` | Home devices on the same Stremio account and LAN | Hosted token manifest generated by configure | Hosted request 307-redirects to the active local host | Desktop app must stay running |
| `Remote Seedbox` | Away-from-home or public HTTPS playback | Hosted token manifest | Public qBit/Prowlarr/file-server ready-file path | Hosted route is ready-file only unless the runtime can serve `/playback` |

## Intended User Flows

### 1. Host Setup

- User configures Prowlarr or Torznab-compatible search plus qBittorrent.
- On Windows, the default runtime state lives under `%APPDATA%\PVTKRRX\runtime` unless explicitly overridden by environment variable.
- Local installs save config to the runtime `local-config.json` on the host PC.
- Hosted installs encrypt config into the addon token.
- Optional Stremio AuthKey linking associates the config with a Stremio account and can derive a stable LAN pair id.

### 2. PC Local

- Install only on the Windows machine that runs PVTKRRX.
- Stremio talks directly to `127.0.0.1:7000`.
- Completed files prefer the built-in `/file/:info` route when the local runtime can read them.
- Not-yet-ready files use `/playback/:info`, which can queue the torrent, wait for playable progress, and then redirect into playback.

### 3. LAN Bridge

- Primary install uses the hosted `stremio://www.pvtkrrx.cc/{token}/manifest.json?mode=hosted` link generated by configure.
- The plain hosted HTTPS manifest is manual fallback only when the client explicitly asks for an addon URL value.
- On the Windows host, the local helper must ask the hosted relay to mint the hosted token; it must not encrypt a hosted LAN Bridge URL with the desktop runtime's local secret.
- The local desktop app publishes heartbeat state to the hosted relay with a pair id, pair key, and active local endpoints.
- Hosted addon requests resolve the current pair and redirect to the live LAN endpoint.
- Redirect preference is:
  - live LAN IP first
  - `.local` alias as fallback/discovery helper
  - loopback not used for non-loopback hosted clients

### 4. Remote Seedbox

- Uses the same hosted config/token model as LAN Bridge.
- Does not depend on the home-LAN heartbeat loop.
- Expects public ready-file playback endpoints and optional external file serving when the host cannot serve files locally.
- Hosted relay behavior is intentionally ready-file-first unless PVTKRRX is self-hosted on a playback-capable runtime.
- Hosted runtime must not emit tracker `/playback` streams because hosted `/playback` is disabled there.
- Remote tracker/download flows must be suppressed when external file-server auth would be required for the eventual redirect.

## Content Model

- Top-level addon types are `movie`, `series`, and `tv`.
- Sports catalog content can be enriched with TheSportsDB posters, thumbnails, and cached artwork lookups.
- Library and sports items use internal `pvtkrrx:` custom ids inside Stremio responses.
- There is no standalone `.pvtk` file format in this repository.

## Playback Rules

- Hosted relay routes do not proxy video data.
- Hosted `/file` and `/playback` must fail fast when the request still depends on local-only serving or buffering.
- Local `/file` serves bytes with range support when the file is locally accessible.
- Local `/playback` is the queued-download path for tracker content that is not yet ready.
- External `fileServerUrl` is optional and mainly for remote/public playback setups.
- Remote buffering URLs must be built only from a provable current file location; otherwise they are suppressed.
- Hosted Remote Seedbox may append info-only stream rows explaining auth-safe suppression or missing current-path proof when those cases hide playback options.

## Security Rules

- Local admin routes are local-network or loopback only.
- Hosted sensitive routes use the browser-origin allowlist.
- Hosted `/test-connection` is rate limited and only allows public HTTP/HTTPS targets.
- `/pair/status` returns the chosen endpoint metadata only to callers that present both `pairId` and `pairKey`.

## Design Rules

1. Raw `http://192.168.x.x:7000/...` addon installs are not a supported primary Stremio install path.
2. `PC Local` is the only supported same-PC install route.
3. `LAN Bridge` is the supported home-device route and depends on the host desktop app remaining online.
4. Hosted LAN-pair installs must be refreshable because stale installed tokens can point at old pair state or route behavior.
5. Root `/manifest.json` must remain a real addon manifest for compatibility with the legacy working Stremio contract.
6. The repo contains historical planning docs from February 2026. They are useful for project history, but they are not the live architecture unless explicitly updated.
